## 与静态网络结构的探索性关系

将同一 100 个 DARTS 架构按字符串 ID 与旧严格发布 `strict_final_release_20261008T000000Z/controls/darts_e0.csv` 的静态结构控制表做完整一对一连接；两边 ID 集合完全相同。初次读取时，合并原始表因混有 RB40 字符名称而把 ID 解析为文本，控制表把 DARTS ID 解析为整数，直接连接报错。只在内存中将控制表 ID 转为文本后，复核交集 100/100、无单边缺失，再计算下列探索性 Spearman：

| 指标 | 指标值与 log 参数量 e0 | 指标值与 log 参数量 e100 | 阶段秩变化与 log 参数量 |
|---|---:|---:|---:|
| TRNAS Φ | 0.976 | 0.974 | 0.001 |
| E37 multiview max | -0.568 | 0.036 | 0.366 |
| 对抗超额特征漂移 | -0.610 | 0.396 | 0.596 |

此处“阶段秩变化”定义为同一模型在 e100 的**原始指标值**秩减去 e0 的原始指标值秩；未按指标方向调整。目标值与 log 参数量的相关为 0.807（100 个架构）。逐个结构控制字段检查时，E37 max 的秩变化与 `sep_conv_5x5` 个数相关 0.314，对抗超额漂移为 0.365；这些是多项事后探索比较，未作确认性显著性声明，也不能解释为算子因果效应。

上述配对进一步缩小了问题：E37/对抗超额漂移的架构排序随训练阶段重排，其中一部分变化与网络规模相关；TRNAS Φ 的架构排序和规模相关性都几乎不变。下一步若采集逐层诊断，须先冻结记录字段、统计方法和完整架构集合，再检查是哪些层级或归一化环节造成这种变化。

## 可以与不可以得出的结论

- 观察事实：E37 九项无一在 DARTS 的 e0/e100 间保留正向的架构排序稳定性；问题不只出在 `max` 或 `RMS` 聚合器。上一轮对抗超额漂移更强地反转。
- 观察事实：TRNAS Φ 的 DARTS 排序几乎不随阶段改变，但既有结构控制诊断显示其原始相关性中可能有结构规模信号；不能据此推断 Φ 的机制已被证明。
- 尚不能断言反转由某个层、算子、宽度或激活尺度造成。严格发布保存的是模型级指标值，当前检查没有逐层原始特征；下一轮诊断须在查看任何新公式结果前冻结记录字段和分组分析，避免事后挑选。
- 不把这份只读诊断作为新指标的预注册或独立验证。下一轮候选仍须另行冻结数学定义、完整 560 行实验、严格发布和独立留出验证。
