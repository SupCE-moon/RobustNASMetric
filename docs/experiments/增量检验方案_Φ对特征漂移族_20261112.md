## 1. 为什么要做这个检验

2026-10-24 的严格榜里，TRNAS 的 Φ（`trnas_consistency_phi`）以八设置均值 **0.782** 排第一，
R-Score 第二（0.738），Ψ 第四（0.598）。

但同一天的另一份分析（`results/audits/metric-redundancy-20261112.md`）显示：
把 85 个指标按「两两秩相关」聚类，ρ ≥ 0.5 时只剩 **21 个簇**，其中最大的一个簇有 **35 个成员**，
清一色是特征漂移的变体（`feature_delta`、`fsp_delta`、`feature_measure_*_delta` 的各种归一化/池化/相对化版本）。
换句话说，**榜单的 84 行里有一大半在测同一件事的不同写法**。

于是出现了两种都能解释「Φ 第一」的可能：

- **H1（有增量）**：Φ 测的是漂移族没测的东西——例如「干净样本与扰动样本的表示是否一致/平滑」，
  而不是「漂移有多大」。它排第一，是因为它多带了一份独立信息。
- **H0（无增量）**：Φ 与真实鲁棒性的相关，只是「漂移小 ⇒ 更鲁棒」这条关系的另一种表达。
  它的数值不与任何单一漂移指标相同（所以自成一簇），但把它放进「漂移族」的回归里，
  不会再解释任何新方差。

现有证据只能说明「Φ 与漂移族的平均相关是 **0.258**（44 个 `feature_measure_*` 指标，
最小 −0.132、最大 0.474；与 `feature_delta` 0.410、与 `fsp_delta` 0.439）」——
既不是 0（不是完全独立），也不是 1（不是同一个东西）。
**0.258 这个中间值，正是必须做检验、而不能靠「它自成一簇」下结论的原因。**

> 边界声明：本检验只回答「信息上是否冗余」。它**不能**证明 Φ 与鲁棒性之间存在因果关系，
> 也不能证明 Φ 的机制就是「表示一致性」——那需要干预实验（改模型、看鲁棒性怎么变），
> 属于第二阶段，成本高得多。

### 2.1 一个必须先讲清的统计事实：560 行 ≠ 560 个独立样本

560 行里，独立单元只有 **204 个架构**：

- RB40：40 个已训练模型，各 1 行；
- NB201：64 个架构 × 5 个训练阶段（e0/e5/e10/e25/e50），同一架构出现 5 次；
- DARTS：100 个架构 × 2 个阶段（e0/e100），同一架构出现 2 次。

同一架构在不同阶段的行**高度相关**（此前测过：Φ 在 NB201 e0 与 e50 之间的秩相关是 0.914，
DARTS e0 与 e100 是 0.995）。把 560 行当独立样本算置信区间，会把区间压得**过窄**、
把 p 值算得**过小**——也就是更容易「显著」，这是最常见的假阳性来源之一。
所以本方案的所有区间和检验都按 **204 个架构**做重采样/置换，而不是按行。

## 3. 三个互补检验

三个检验回答同一个问题的不同侧面，事先声明 **T1 为主检验**，T2、T3 只作支持性证据。

### T1 偏秩相关（主检验）

对每个设置 s：

1. 把 `target`、Φ、以及「漂移族基准」 B 三者都转成秩；
2. 用 `target` 对 B 做秩回归，取残差 r_y；
3. 用 Φ 对 B 做秩回归，取残差 r_Φ；
4. 算 `rho_s = spearman(r_y, r_Φ)`。

八个设置取平均得到 **Δρ**，即「扣掉漂移族能解释的部分之后，Φ 还剩多少排序能力」。

**B 怎么定**：取「漂移族基准」= ρ≥0.5 聚类里那个 **35 成员簇**的成员（`feature_delta`、`fsp_delta`
以及 `feature_measure_*_delta` 的各变体；注意 `feature_measure_` 前缀共 44 个，不是全部都在这个簇里）。
在每个设置内，把这 35 个指标先按方向统一成「越大越好」，再取**平均秩**作为 B。
主检验用平均秩（自由度少、不依赖 PCA 的符号约定）；PCA 第一主成分只作稳健性检查。

### T2 嵌套模型 + 分组交叉验证

- 模型 A：`target_rank ~ B`（B 取前 k 个主成分，k=1..3）
- 模型 B：`target_rank ~ B + Φ_rank`
- 比较调整后 R² 的提升 ΔR²；
- 交叉验证必须**按架构分组**（同一架构的所有阶段行要么全在训练集、要么全在测试集），
  否则模型会「记住」同一个架构，ΔR² 虚高。

### T3 分层内排序

把样本按 B 分成 5 层（五分位）。如果 Φ 的预测力只是漂移的另一种写法，
那么在**同一层内部**（漂移程度相近的模型之间）Φ 与 target 的相关应该接近 0。
逐层算 Φ 与 target 的秩相关，看是否仍稳定为正。

## 4. 显著性怎么算

- **按架构聚类 bootstrap**：重采样 204 个架构（有放回），每个被选中的架构连同它在所有设置里的行一起进来；
  重复 B=2000 次，得到 Δρ 的经验分布与 95% 百分位区间。
- **置换检验**：在设置内打乱 target（按架构整体打乱，保持同一架构的阶段行绑定），
  重复 2000 次，得到「无关系」的零分布，算单侧 p 值。
- 随机种子固定 **20261112**，写在脚本参数里并记入报告。

## 5. 判定标准（事先写死，避免事后挑好看的解释）

| 结果 | 结论怎么写 |
| --- | --- |
| T1 的 95% CI 下界 > 0 且置换 p < 0.05 | 「在扣除漂移族可解释部分后，Φ 仍有统计可辨的增量排序能力」 |
| T1 不显著，且 T2/T3 方向一致接近 0 | 「**没有证据**表明 Φ 在漂移族之外提供增量；它的榜首可由既有漂移信息解释」 |
| T1 显著但 T2/T3 不一致 | 「结果不稳，需先查清是 B 的构造方式还是分层方式导致，暂不下结论」 |

注意第二行写的是「没有证据表明有」，**不是**「证明了没有」。204 个架构的样本量，
对「中等偏小」的增量本来就检不出——这个界限要写进报告。

## 6. 已知局限（提前写，避免结论被过度解读）

1. **target 来源不齐**：RB40 用公开报告的 AutoAttack/PGD 鲁棒准确率，NAS 网格用固定协议训练的 PGD 值。
   两类混在一起可能引入异质性，因此**必须**额外跑一次「只 RB40」「只 NB201」「只 DARTS」的分网格敏感性分析。
2. **只用 85 个指标**：第 86 个（adv-excess）原始行在服务器，本次缺失；结论只覆盖 85 个。
3. **B 的选择有任意性**：主成分 vs 平均秩、k 的取值都会影响 Δρ 的大小。所以主检验用「平均秩」这个
   最简单、最少自由度的版本；PCA 版本只作稳健性检查。
4. **只能谈信息，不能谈机制**：即使 T1 显著，也只能说「Φ 携带了漂移族没有的排序信息」，
   不能说「Φ 因为测了一致性所以有效」。
