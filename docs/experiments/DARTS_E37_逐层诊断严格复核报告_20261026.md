日期：2026-10-26。**本报告取代 2026-10-25 结果报告中的验收声明；旧报告与 `verifications/v1/` 均保留为原始过程记录。** 实验范围、九项指标表、39 个分量的描述性结果及非因果解释，详见 `DARTS_E37_逐层诊断结果与问题记录_20261025.md`。本复核没有重跑 GPU、改写 200 条原始尝试、变更原 E37 公式或修改任何 strict/E36/E37 历史发布。

## 复核缘由和修补

独立只读审查指出 `v1` 核验器虽能检查 200 键完整性与保存的九项模型分数，却有四处未闭合的验收链：未逐项从存储的层分量重建九项分数；未强制核验锚层原始序号；每条尝试中的协议及新诊断采集代码版本未完整绑定；分析脚本允许同 ID 但不同数值的控制表。审查用有限 channel 污染、删去/重复锚层序号、改协议、替换同 ID 控制表等内存构造复现了 `v1` 的误通过。审查**没有发现实际 200 条采集公式有误**，但在补强前，`v1` 的 PASS 不足以单独证明逐层数据可解释。

现已加入失败先行的回归测试并分别修补：

1. 核验器从每张图的 3 段 flow、4 层 channel/spatial/spectrum，按冻结 E37 聚合式独立重算全部九项分数，逐键同时与保存分数和严格发布比较；旧的 `abs=3e-8, rel=3e-5` 容差未放宽。有限但错误的分量现会 FAIL；无效分母会给出失败证据，而不使核验崩溃。clean/adv 尺度分量并非九项公式的输入，不能仅凭九项分数证明其原始张量数值正确，其可信度仍依赖冻结采集源码和保存的运行来源。
2. 四个 `anchor_index` 必须是严格整数，逐项等于原 `_anchor_indices(feature_count, 4)` 的选择；两个阶段同时缺失或同错也不能通过。模块路径、调用号、形状及 100 对身份匹配继续保留。
3. 逐条记录的三项显式协议字段必须等于冻结 manifest 的 `epsilon`、64 样本、批量 1；之后的运行器还会逐条写入新增诊断采集器与运行器 SHA-256。2026-10-25 的原尝试在该字段上线前产生，**没有倒填或改写**，而是以新建的 `legacy_attestation_v1.json` 把当时预运行的 v4 代码哈希文件、正式启动日志和全部 200 个原始 JSON 的字节哈希绑定起来。该文件于实验后创建，只是可审计的**事后字节绑定，不是独立的逐键执行证明**。未来若采集代码变化，应另立版本，不能把新旧来源无说明地混进同一发布。
4. 分析入口现在要求原冻结 manifest、严格对应的控制表路径与 SHA-256、以及核验输出的 canonical JSONL SHA-256。具有相同 100 个架构 ID 但数值不同的控制表会被拒绝；对分析输入的修改也会被拒绝。

## 研究结论与下一步边界

复核增强的是**诊断数据的内部一致性和来源约束**，并没有把相关性变成因果证明。E37 九项在固定 DARTS 架构的 e0/e100 排序仍不稳，部分逐层变化与静态网络规模相关；多层、多分量比较仍是探索性的。不能据此宣布已有 Ours 超过 TRNAS Φ。下一候选必须另立数学定义、方向与完整三空间 560 键预注册，获得书面设计和实施计划批准后才启动；正式胜出须完整主榜胜过 TRNAS Φ 且独立留出支持。目前 RB40 独立留出权重仍只有 10/11 可加载，NB201/DARTS 历史候选缺相应检查点，不能声称三空间独立验证完成。
