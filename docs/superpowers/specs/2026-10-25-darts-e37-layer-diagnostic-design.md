# DARTS E37 跨阶段逐层诊断设计

状态：**对话设计已确认；本文待用户审阅。尚未实施、运行 GPU 或产生新指标。** 日期：2026-10-25。

## 1. 目的与边界

现有严格发布表明：同一批 100 个 DARTS 架构的 e0/e100 目标值逐个相同，但 E37 九项指标的架构排序在训练阶段间不稳定；TRNAS Φ 的阶段排序较稳定。只读证据见 `docs/experiments/DARTS跨阶段指标翻转只读诊断_20261025.md`。本诊断要定位 E37 的层级响应、归一化或跨层聚合中哪些变化伴随排序反转，并检查这些变化与静态网络规模的关系。相关关系不能证明训练、规模或某个算子造成了反转。

本设计**不是**新指标预注册、560 行正式实验、独立验证或总榜更新。不得用这 200 个诊断键的结果选出一个未经单独冻结公式的候选并直接入榜。后续 Ours 候选必须另立定义、出处和预注册清单，完整运行 RB40 40 + NB201 320 + DARTS 200 = 560 行，经过严格发布与独立验证后，才能判定是否超过 TRNAS Φ。

## 2. 冻结输入与来源

- 唯一范围是严格主网格的 DARTS 100 个架构，各取 e0 和 e100，共 **200 个精确 `(architecture_id, stage)` 键**；不挑选架构、不换检查点、不缩小完整性门槛。架构 ID、检查点、目标值及基准分数均取 `wangjiahao` 容器内 `/workspace/robust_metric_lab_nas/outputs/student_metrics/wangjiahao/strict_adv_excess_release_20261024T110422Z/` 的严格发布和原 E37 清单；先保存清单与文件哈希，不修改其内容。
- 重用 E37 的冻结协议：CIFAR-10 测试集从 offset 0 起的 64 张图，原顺序、原标签、原预处理、FGSM、`epsilon=8/255`、`seed=20260808`、`batch_size=1`、`ActivationRecorder(activation_mode="all_leaf")` 和 `_anchor_indices(..., max_layers=4)`。以原 E37 manifest 和运行源码哈希为准；若无法复原该组合，停止而不把近似实现当作同一实验。
- 只操作 `wangjiahao` 容器的 `/workspace/robust_metric_lab_nas` 和指定本地 RobustMetric 隔离工作区。旧 v3/E36/E37、TRNAS、严格发布及 RACL 排除证据均只读。新运行清单、尝试批次、分析和失败证据置于独立命名目录。
- 运行前记录 E37 原源码、环境、输入清单、静态结构控制表与参考严格发布的哈希。用于比较的参数量取既有 `strict_final_release_20261008T000000Z/controls/darts_e0.csv`，按字符串架构 ID 一对一连接；必须先证明两边集合相同且无重复。

## 3. 采集组件与数据流

逐个键加载同一检查点并生成同一 64 张图的 clean/FGSM 前向。沿用原 E37 的叶模块 4D 特征收集和最多 4 个等距锚层选取，不改变攻击或模型级指标公式。新增的诊断记录器只暴露可审计的锚层元数据与数值分量，保持旧 E37 计算入口和注册表不变。

每键记录：架构 ID、阶段、检查点/清单哈希、样本/协议和源码哈希、状态、耗时、峰值显存、全部可用 4D 输出数；每个锚层的原始输出序号、限定模块路径及同模块调用序号、clean/adv 张量形状。对于相同架构，e0/e100 的锚层序号、身份与形状必须可配对；不一致时保留事实并停止该架构的层级配对分析，不能改选层或丢弃架构。

对每个样本、每个锚层，仅保留有限数值汇总：clean/adv 特征尺度（均方根与中心化范数）及 E37 原有通道、空间和谱分量；对每对相邻锚层保留原有 flow 分量。另保存这些分量的 64 样本等权均值和原 E37 九项模型级重建分数。**不保存原始图像、扰动张量或激活张量**，不保存最终鲁棒性标签到逐层明细表。数值字段的算法必须与原 E37 对应函数一致；不得根据结果临时替换归一化、分母或层聚合。

诊断数据流为：冻结清单 → 每键只读模型/样本加载 → 同次 clean/FGSM 前向 → 数值汇总和九项 E37 重建分数 → 与严格发布逐键核对 → 完整性检验 → 预定分析。所有尝试输出保留原始键与错误，不通过直接重跑同一个 CSV 覆盖失败行；现有运行器会把失败行视为已存在键。

## 4. 预定分析及解释限制

以完整 100 个架构配对，不按分数或模型大小筛样本。先报告九项 E37 模型分数在 e0/e100 间的 Spearman，并与既有严格发布核对；再对四个锚层和三段相邻 flow 分别报告 clean/adv 尺度、原有 E37 分量的 e0/e100 架构秩相关、同架构数值变化的分布，以及这些变化与 `log(parameter_count)` 的 Spearman。秩变化统一定义为 e100 的原始数值秩减 e0 的原始数值秩；同时明确每个正式指标原方向，避免把数值秩误称为性能秩。

每项逐层分量均用相同的 100 个配对架构计算；零方差导致秩相关未定义时，原样报告并禁止以删架构修复。诊断图表按锚层序号展示全部预定分量，不事后只展示最有利层。可用既有静态控制做描述性分层或秩相关，但所有层/分量/结构字段比较均标为探索性多重比较，不给单个相关性因果或确认性显著性解释。若分量和网络规模共同变化，只能提出下一轮可证伪假设，不能凭此宣称消除了结构混杂。

## 5. 失败、资源与验收

- 运行前使用现有显存监控机制等候足够空闲显存；不停止、挤占或重配他人进程。先做只用于实现一致性和资源估计的少量键 smoke test，不依据它调整研究假设或挑选模型；正式诊断仍须覆盖全部 200 键。
- 每个尝试批次不可变，保存 `status`、错误类型、原始堆栈、日志及键。OOM、缺权重、非有限值和层身份不一致均不可伪造为成功。修复仅对精确失败/缺失键建立新批次；合并时验证同一键只有一个可接受成功记录，旧失败证据仍可追溯。若为修复而改变定义或源码哈希，建立新版本，不能与旧尝试无说明混合。
- 验收需要 200/200 精确键、唯一、全部数值有限、`status=ok`、每键 64 张样本及预定锚层/相邻分量齐全，且原 E37 **九项**重建模型分数逐键匹配严格发布。数值比较先用现有 E37 分块等价测试的 `rel=3e-5, abs=3e-8` 作为固定容差；同时输出最大绝对/相对误差。任一键、任一项超差则停止机制解释并调查，不因方便而扩大容差或删除键。若旧发布的序列化精度不足以支持该容差，先保留对比证据并请求修订方案，不自动放宽。
- 对同架构 e0/e100 的层身份/形状配对也要求 100/100 可解释；如客观不匹配，则完整报告差异，暂不作该架构的层级因果解释或以剩余架构冒充全量结论。分析脚本必须能从冻结清单和不可变尝试批次重建完整性报告、配对表、图表与误差表。
